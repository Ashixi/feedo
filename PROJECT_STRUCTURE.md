# Feedo Protocol: Архітектура та Структура Проекту

## Про проект
**Feedo** — це гібридна децентралізована P2P мережа наступного покоління, розроблена для створення стійкої до цензури екосистеми поширення контенту. Проект поєднує можливості відкритого протоколу **Nostr**, потужність штучного інтелекту (**векторний семантичний пошук**) та високу продуктивність завдяки гібридній архітектурі.

Замість того, щоб кожна нода зберігала 100% контенту інтернету, Feedo використовує розумний математичний шардинг. Вузли автоматично розподіляють навантаження з моніторингу релеїв, агрегуючи контент в єдиний децентралізований індекс.

---

## Загальний Огляд Директорій

*   `/feedo/` — Основний код гібридної ноди (Rust P2P Core, Python Semantic API, Парсери).
*   `/feedo_sdk/` — Бібліотеки (SDK) для розробників, які створюють dApps.
*   `/feedo_explorer/` — Веб-інтерфейс адміністратора ноди та моніторингу мережі (Frontend).
*   `/contracts/` — Смарт-контракти токеноміки.

## Детальний Опис Компонентів Ноди (`/feedo/`)

Директорія `/feedo` є коренем для розгортання гібридної P2P-ноди. У версії V2 ми відмовилися від повільного Python P2P на користь високопродуктивного Rust-ядра.

### 1. Feedo Core (`/feedo/feedo-core/`)
Написано на **Rust**. Це "серце" вузла, яке відповідає за низькорівневий транспорт, P2P-зв'язок (Gossipsub, Kademlia DHT), криптографію та Nostr-з'єднання.

*   `src/main.rs`: Головний файл гібридної ноди. Ініціалізує `libp2p` Swarm, обробляє Gossipsub-повідомлення, Kademlia-маршрутизацію та REST-ендпоінти для локального зв'язку з Python (`/local/network_info`, `/local/publish`).
*   `src/bin/feedo_nostr.rs`: Власний гібридний Nostr WebSocket-релей на базі `axum`. Приймає з'єднання клієнтів (NIP-01, 11) та вміє перенаправляти пошукові запити (NIP-50) до векторної бази Python.
*   `src/pbft.rs`: Керування консенсусними повідомленнями та криптографічними підписами.
*   `src/eth_bridge.rs`: Модуль взаємодії з EVM блокчейнами (Polygon) для перевірки балансів та смарт-контрактів.
*   `src/proto.rs`: Обгортка для серіалізації/десеріалізації швидких Protobuf-повідомлень.

### 2. Feedo API (`/feedo/feedo-api/`)
Написано на **Python** (`FastAPI`). Модуль інтелектуальної обробки, який керує базою даних, векторним пошуком та надає зручний REST API для клієнтів.

*   `main.py`: Точка входу FastAPI. Керує життєвим циклом програми, ініціалізує LanceDB, Postgres, запускає фонові задачі (наприклад, `background_stats_updater`).
*   `api_v1/`: Маршрутизатори API (REST).
    *   `content.py`: Обробка та публікація контенту.
    *   `semantic.py`: AI-пошук (через LanceDB), кластеризація та генерація "розумних" стрічок.
    *   `node.py`: Телеметрія ноди, статистика та підключення пірів.
*   `models.py`: Схеми реляційної бази даних PostgreSQL (SQLAlchemy + asyncpg).
*   `unified_monitor.py` (Live Parser): Система реального часу, яка парсить нові пости за допомогою динамічного шардингу (розподіляє пули релеїв між нодами в залежності від `PeerId`).
*   `backfill_nostr.py` (Spider Parser): Історичний парсер ("павук"), який іде назад у часі для завантаження старих постів, так само використовуючи механізм шардингу.
*   `tokenomics_service.py`: Інтеграція з балансами та смарт-контрактами бази даних.

### 3. Feedo Parser (`/feedo/feedo_parser/`)
Написано на **Python**. Модуль для роботи з зовнішніми джерелами даних (Nostr, RSS тощо) та їх векторизації.

*   `content_sources/nostr_source.py`: Логіка виявлення релеїв (Discovery), читання Nostr-подій та їх валідація. Реалізує ключовий алгоритм поділу релеїв між нодами мережі (`my_relays = sorted_relays[node_index :: total_nodes]`).
*   `vector_brain.py`: Відповідає за машинне навчання та NLP. Використовує `sentence-transformers` (оптимізовано через ONNX) для генерації векторів контенту та зберігає їх у LanceDB (в директорію `/db_data/lancedb`).
*   `crypto_utils.py`: Інструменти для створення та перевірки підписів (Schnorr, Ed25519) за стандартом Zero Trust.

### 4. Protobuf Схеми (`/feedo/proto/`)
*   `feedo.proto`: Спільна мова обміну даними між Rust та Python. Дозволяє швидку та суворо типізовану взаємодію замість повільного JSON.

## Інфраструктура Розгортання (Docker)

Feedo розроблено для легкого запуску на будь-яких серверах за допомогою Docker.

*   `Dockerfile.hybrid`: Мульти-етапна збірка. Спочатку компілює Rust-ядро (`feedo-core` та `feedo-nostr`), потім переносить їх у легкий Python-образ, встановлюючи ML-залежності.
*   `start-hybrid.sh`: Баш-скрипт для одночасного підняття Rust P2P Core, Nostr Relay та Python FastAPI всередині одного контейнера.
*   `docker-compose.yml`: Шаблон для запуску повного стеку (`PostgreSQL` + `feedo_hybrid_node`).

## Життєвий Цикл Даних (Data Flow)

1.  **Парсинг/Завантаження:** Фоновий процес (`unified_monitor.py` або клієнтський API-запит) отримує контент з мережі Nostr або безпосередньо від користувача.
2.  **Шардинг та Фільтрація:** Нода перевіряє свій `node_index`, щоб впевнитися, що джерело належить їй, і усуває дублікати (in-memory deduplication + Postgres Unique Constraint).
3.  **Векторизація:** Контент обробляється нейромережею (`gte-multilingual-base`), генерується 768-вимірний вектор.
4.  **Зберігання:** Текст, метадані та вектор зберігаються у локальній базі (`PostgreSQL` + `LanceDB`).
5.  **P2P Синхронізація (Gossip):** Rust-ядро розсилає повідомлення `PeerAnnounce` іншим нодам мережі про оновлення статистики індексованих постів (забезпечуючи децентралізований Discovery).
6.  **Пошук та Видача:** Клієнт робить запит на `/explorer/search`. База шукає найближчі семантичні вектори та миттєво повертає результати через швидкий API.

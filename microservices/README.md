## Етап 3: Storage-Node як P2P Gateway (04 Липня 2026)

### Що було зроблено
1. **Оновлення залежностей**:
   - В `Cargo.toml` було додано фічу `ws` до пакету `axum`, щоб включити підтримку WebSocket з'єднань.
2. **REST API для публікації (`POST /api/v1/pubsub/publish`)**:
   - Реалізовано обробник `handle_publish` в `main.rs`. Клієнти можуть відправляти JSON. Дані коректно серіалізуються і через `SwarmCommand::Publish` відправляються в gossipsub мережу.
3. **WebSocket API для підписки (`GET /api/v1/pubsub/subscribe/:topic`)**:
   - Реалізовано `handle_subscribe` та `handle_ws` в `main.rs`. При підключенні нода підписується на топік, і всі повідомлення відправляються у WebSocket у вигляді бінарного повідомлення.
4. **Розширення P2P Swarm**:
   - Розширено `SwarmCommand` (`Publish` та `SubscribeTopic`).
   - Додано `tokio::sync::broadcast` канал (`gossip_tx`), через який отримані з P2P мережі повідомлення роздаються на всі активні підключення WebSocket.

## Етап 6: Повна Децентралізація Consensus-Node (04 Липня 2026)

### Що було зроблено
1. **Мережевий Шар (`network.rs` та `swarm_loop.rs`)**:
   - Додано `libp2p` стек із вбудованими протоколами: `Gossipsub`, `Kademlia` (для DHT маршрутизації), `Identify` та `mDNS`.
   - Створено асинхронний цикл (`swarm_loop.rs`), який працює у фоні та відстежує всі мережеві події консенсусу.
2. **Інтеграція Gossipsub Топіків (`main.rs`)**:
   - `feedo_consensus_pbft`: Нода підписується на цей топік. Щойно туди падає нове повідомлення (наприклад `PrePrepare`), нода віддає його у свій `pbft_manager`, який обчислює підписи, міняє стадії, і публікує відповідь (наприклад `Prepare` або `Commit`) назад у цей же топік.
   - `feedo_name_registrations`: Синхронізація доменних імен між нодами. Щойно приходить JSON із новим доменом, він додається локально в `name_db`. Уся мережа матиме ідентичний стан `name_db`.
   - `feedo_did_updates`: Зарезервований топік під оновлення DID.
3. **Підключення до gRPC**:
   - Канал передачі подій (`swarm_tx`) ін'єктовано безпосередньо у `MyConsensusService`. Тепер будь-який RPC виклик або внутрішня логіка PBFT може миттєво відправити подію по всій P2P мережі.
